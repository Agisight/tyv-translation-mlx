# AGENTS.md

Инструкции для ИИ-агентов (Claude Code, Codex и др.), работающих в этом репозитории.

## Цель проекта

LoRA-дообучение небольшой LLM (сейчас Qwen3-1.7B, 4 бита) на русско-тувинском
параллельном корпусе с помощью MLX на MacBook Air M4 (16 ГБ), затем запуск
модели на Mac и iPhone. Результат сравнивается с NLLB-моделью автора по chrF++.

## Окружение

- macOS, Apple Silicon (arm64), MacBook Air M4, 16 ГБ памяти, без кулера.
- Python 3.12 из Homebrew в `.venv` (системный `python3` — 3.9, не использовать). Перед любой командой:
  `source .venv/bin/activate`
- Основные библиотеки: `mlx-lm[train]`, `datasets`, `sacrebleu`.
- Оболочка zsh: не добавляй комментарии `#` в команды, которые пользователь вставит в терминал.
- Места на диске мало (~20 ГБ свободно). Не скачивай лишние модели и чекпойнты без спроса.
- Перед `mlx_lm.convert` с Hugging Face нужен полный снапшот: `hf download <repo>`,
  иначе `IncompleteSnapshotError` при сохранении.
- Текущий статус проекта — в разделе «Статус» файла `EXPERIMENTS.md`. Обновляй его после каждого шага.

## Файлы

- `prepare_data.py` — скачивает `Agisight/tyv-rus-200k` (колонки `tyv`, `ru`),
  чистит, делит без утечки по тувинской стороне, пишет `data/*.jsonl` в chat-формате.
- `lora_config.yaml` — конфиг для `mlx_lm.lora`.
- `tyv_translate.py` — единственное место, где собирается промпт для инференса.
- `translate.py` — ручная проверка одной фразы.
- `evaluate.py` — chrF++ (`CHRF(word_order=2)`) по `data/eval_pairs.jsonl`.

## Команды

```bash
python prepare_data.py
mlx_lm.lora --config lora_config.yaml
python translate.py "Как ваше здоровье?"
python evaluate.py --limit 500
mlx_lm.fuse --model models/qwen3-1.7b-4bit --adapter-path adapters --save-path models/tyv-qwen3-1.7b
```

## Правила

1. **Формат промпта должен совпадать при обучении и инференсе.** `PROMPTS` и `SYSTEM`
   определены в `prepare_data.py` и импортируются в `tyv_translate.py`. Меняешь формат —
   пересобирай данные и переобучай адаптер.
2. **Qwen3 — модель с режимом рассуждений.** Для перевода он отключён:
   `enable_thinking=False` в `apply_chat_template`. Не убирай это.
3. **Тест-сет не должен пересекаться с train.** Для сравнения с NLLB используется
   тот же тест-сет, что в статье (`--test-file`). Не меняй метрику и не «улучшай» цифры
   за счёт другого теста.
4. **Долгие операции** (обучение, полный `evaluate.py`, скачивание моделей) не запускай
   без явной просьбы пользователя. Сначала предложи команду.
5. **Память 16 ГБ.** При OOM сначала `batch_size: 4`, потом `max_seq_length: 96`,
   потом `num_layers` меньше. Не поднимай размер модели без спроса.
6. **Не коммить** `models/`, `data/`, `adapters/`, `.venv/` (см. `.gitignore`).
7. **Факты для статьи и резюме:** NLLB-модель автора — дообучение модели Meta
   на основе кода David Dale (с его консультацией), а не написанная с нуля.
   chrF++ NLLB v3: 48.5 (ru→tyv), 48.1 (tyv→ru). Не приписывай результатов,
   которых нет в логах.

## Журнал экспериментов

Записывай каждый прогон в `EXPERIMENTS.md`: дата, модель, ключевые параметры конфига,
It/sec, финальный Val loss, chrF++ в обе стороны, короткий вывод.
